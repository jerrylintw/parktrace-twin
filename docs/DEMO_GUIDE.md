# 期中展示流程與報告建議（約 6–8 分鐘）

## 主題主張

> **ParkTrace Twin：不只記錄誰停在哪裡，也能找出「系統以為的車位」與「現場觀測的車位」之間的落差。**

## 操作腳本

1. **空場狀態（30 秒）**：打開首頁，介紹 3 排 × 6 個車位。A01 是無障礙車位，C01–C03 為充電車位。切到資料結構實驗室展示二維陣列。
2. **進場（60 秒）**：輸入 `AAA-1001` 登記一般車，看看自動分到哪個最短步行距離的一般格。再輸入 `EV-2002` + 電動車，看它分到 C01。提醒老師記錄不會只放 JS LocalStorage，而是後端 DB。
3. **異常觀測（60 秒）**：回首頁「車位觀測模擬」選剛剛一般車的車位，輸入 `ZZZ-9999`，按更新。系統原本分配與實際觀測不同，立即出現紅色告警。把車牌清空可消除。
4. **模擬快轉 + 收費（60 秒）**：先快轉 60 分鐘，再輸入 `AAA-1001` 出場，畫面會顯示 NT$40，完成的帳單出現在車輛與帳單頁面。講解 `ceil((60-10)/30) × 20 = 40`。
5. **FIFO（90 秒）**：為一般車格連續登記共 14 台一般車，再登記第 15 台，新車進候補。讓其中一台已停車出場，候補隊首立即自動分配空車位，開始計費。
6. **四大資料結構（60 秒）**：切換「資料結構實驗室」，講 2D Array、Queue、Stack、雙向鏈結串列；說明何時使用，以及程式碼位置。
7. **時間軸回放（45 秒）**：進事件時間軸，點某次 ENTRY 與 OBSERVE 比較「當時狀態」。這是本組的差異化創意。
8. **OCR（選配 45 秒）**：在網頁左上方按「啟動筆電鏡頭」，允許相機權限，拍攝紙上印出的 `ABC-1234`，框選後按「辨識車牌」。說明 OCR 使用多種影像前處理，候選依多次辨識一致次數排序，但仍必須人工核對才能正式登記。使用後鏡頭會自動關閉。

## 老師可能問的問題

**Q：你做的跟一般停車場有什麼差別？**  A：分配與觀測雙軌資料、衝突告警、事件快照回放，以及將四種資料結構透明呈現在前端。

**Q：Queue 是真的 FIFO 嗎？**  A：後端將候補表依遞增 `id` 排序，補位只取隊首；實體教學資料結構使用 `collections.deque`，O(1) 兩端操作。可用「填滿一般車格 → 候補兩台 → 連續出場」證明順序。

**Q：Stack 有做到後進先出嗎？**  A：把後端事件依時間由舊到新 Push 進 Python list，再從頂端 Pop 輸出。Stack 是最近操作展示，不是直接刪除不可逆金流日誌。

**Q：鏈結串列沒有只是 Python list 嗎？**  A：在 `structures.py` 明確定義 `VisitNode(prev, next)` 和 `ActiveDoublyLinkedList`，可示範節點連接及刪除頭、中、尾節點。

**Q：為什麼還要資料庫？**  A：資料結構管理應用層狀態與演算法，資料庫則確保重啟後收據、車位及事件持久存在；兩者是不同層。

**Q：OCR 準確率多少？**  A：這個版本使用 Tesseract + 影像增強與人工確認，沒有大規模車牌測試集，因此不能報告特定準確率；應展示成功/失敗的情境和改善方法。

**Q：是不是 AI 就算創新？**  A：真正創新不在依賴 OCR，而在 **系統分配 vs. 現場觀測的差異偵測** 與 **事件回放**。
